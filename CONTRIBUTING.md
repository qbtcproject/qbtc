# Contributing

State the network profile, source commit, operating system, compiler and exact reproduction steps. Use disposable wallets and chain directories. Do not include passwords, wallet files, private keys, private Tor-service files or control secrets in an issue.

For changes, explain the problem, intended behavior and relevant validation. Keep consensus behavior changes separate from desktop/policy fixes. Add a regression when fixing a security-sensitive bug. Never change the frozen candidate genesis or difficulty implicitly.

GitHub Issues can track reproducible non-sensitive bugs; Discussions, if enabled by the owner, can host design questions. The internal review is not an independent audit. Do not describe the system as audited or absolutely quantum-proof.
