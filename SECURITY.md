# Security policy

QBTC is experimental. There is no independent audit, guaranteed market value or bug-bounty commitment. See public-release/SECURITY-REVIEW-2026-10-24.md for the latest scoped internal review.

For a potentially exploitable vulnerability, use GitHub private vulnerability reporting if the owner has enabled it. No private reporting channel has yet been confirmed for this new repository; do not assume public issues are confidential. You may open a non-sensitive issue asking the maintainer to arrange a private channel without including exploit details or secrets.

Never send a wallet, password, signing key, control secret or private Tor-service key. Report affected source commit/profile, impact, reproduction on disposable data and mitigation ideas. Avoid testing against other people's running nodes without permission.
